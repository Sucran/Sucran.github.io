We discussed how **Transformers** process images by dividing them into small patches, effectively creating a sequence. Images are divided into S×S patches—in this example, perhaps 3×3.

Each patch is represented by a **token**, typically by linearly projecting the reshaped image into a vector. These tokens are D-dimensional vectors, as shown in this slide.

However, by converting images into patches, we must consider what information might be lost in this process.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image10.png)

This process essentially loses the **spatial position** and **two-dimensional positional information** of the image. To address this problem, we introduce **positional embeddings**.

There are multiple ways to implement positional embeddings. One method is to create a sequential numbering system (1, 2, 3, etc.), while another adopts **two-dimensional coordinates** (X and Y).

These embeddings are combined with the original tokens and then processed by **Transformer layers**—which contain self-attention mechanisms, layer normalization, and the MLP components discussed earlier. The final output layer generates vectors suitable for various applications.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image11.png)

One of the main applications of computer vision is image classification.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image12.png)

In **image classification** tasks, the core goal is to generate outputs that effectively represent categories through encoding. To achieve this, we typically introduce a **special token**—injected as additional input into the Transformer, with dimensions consistent with other inputs. This token is a learnable parameter, and its output representation is converted into a class probability vector (specifically a \\(C\\)-dimensional vector). This method is commonly called a **class token**.

This is one of the most basic and standard implementations when applying Vision Transformers (ViT) to image classification tasks. However, Transformer applications extend far beyond classification tasks and can adapt to many other tasks, some of which we will explore today.

Last week we also discussed another Transformer variant, which operates based on the same token mechanism.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image13.png)

Starting from these tokens, we enter the Transformer layer processing flow. As mentioned earlier, these layers consist of multiple Transformer modules. **Positional embeddings** are added to the input. Unlike language processing that requires masking to prevent future information leakage, here we can process the entire image simultaneously without masking. The Transformer outputs vector representations for each input image patch.

There are mainly two methods for training Transformers in this scenario. The **first method** uses independent class tokens, while the **second method** takes all output tokens and projects them into a probability vector representing C class predictions through pooling operations. These two architectures represent the main variants of Transformer-based classification models.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image14.png)

We use the same supervised method discussed earlier: performing backpropagation by defining loss functions (**binary cross-entropy**, **softmax**, and **maximum loss**). This essentially encapsulates the core idea of Vision Transformers (ViTs).

Over the years, this architectural approach has remained consistent across different applications. Many modern architectures still use these components, highly similar to the framework proposed in this paper.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image15.png)

The slides from last week discussed several optimization methods, which I will briefly outline. It's important to understand that there are numerous fine-tuning and optimization techniques that can improve performance and stabilize the Transformer training process.

One key optimization involves **residual connections**. In this configuration, layer normalization is applied outside the residual connection, i.e., normalizing the output. However, this method limits the model's ability to replicate the identity function—which is the core characteristic that **ResNet** strives to achieve. The solution is to integrate layer normalization into the residual path.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image16.png)

We typically place **normalization** operations before the self-attention layer and apply them again before the MLP layer, while preserving the identity mapping. There are other normalization methods, such as **RMS Norm** (root mean square normalization), which provides a cleaner implementation by excluding feature means. Empirical studies show this effectively improves training stability. Although there are theoretical foundations, the main motivation for adopting these methods lies in their stabilizing effect on the training process.

Another improvement is replacing standard MLPs with **gated variants** like SwiGLU MLP. This method introduces gated nonlinear mechanisms in ternary weight matrices (adding a new matrix beyond traditional w1 and w2), increasing trainable parameters and enhancing nonlinear expressive capabilities while keeping the network parameter count unchanged (even when setting the hidden layer dimension to \\(\frac{8}{3}\\)).

Finally, modern architectures commonly adopt **mixture of experts** mechanisms. Unlike single MLPs, this scheme deploys multiple expert MLPs and assigns tokens to specific experts through routing mechanisms, activating only some experts (A out of E) during each processing. This method expands parameter capacity and improves model robustness without excessively increasing computational overhead.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image17.png)

These are all parallel multi-layer perceptrons (MLPs) that enable multiple expert models to operate simultaneously. As mentioned earlier, they are applied in all large language models (LLMs). To our knowledge, all modern LLMs currently adopt these improvement schemes.

Here's a summary of the adjustment points I just discussed. Is this similar to bias? Not quite.

![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image18.png)

This is a **trainable parameter** that can be optimized through feedforward networks or converted into a probability vector through simple linear projection. It's not merely a bias term.

Note that there are multiple **self-attention layers** in the model, which integrate information by establishing interactions between all tokens and the class token. Under this supervision mechanism, the loss function acts on the class token, which represents the class probability vector.

This leads to a key question: How can we intuitively understand the specific roles of different expert modules in this framework?



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image19.png)

Since they are trained in parallel and initialized differently, these models typically learn **distinctly different** but sometimes closely related aspects.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image20.png)

However, this method mainly involves increasing computational resources and parameter count, enabling the network to learn diverse concepts when necessary. For example, when modeling multiple probability distributions, these multi-layer perceptrons (MLPs) typically have the ability to distinguish different data modalities.

The ensuing question is whether the number of experts belongs to **hyperparameters**. Indeed, it belongs to the hyperparameter category. Based on current knowledge, this value is usually predetermined. While excessive fine-tuning should be avoided, the fact that these parameters essentially belong to hyperparameters always holds.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image21.png)

In the initial few lessons, we spent considerable time exploring how to develop a **classifier** that classifies images from pixels to labels.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image27.png)

However, another equally important task is semantic segmentation.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image28.png)

In **semantic segmentation** tasks, our goal is to assign a label to each pixel in the image, thereby converting each pixel into a label for the corresponding object or element in the scene. When training such models, our goal is to input images during inference and output segmentation maps.

There are multiple ways to achieve this goal. One simple and crude approach is to examine each pixel individually and predict its label. However, this method has fundamental flaws because individual pixels lack **contextual information** and cannot determine which object they belong to. Context is crucial—surrounding areas must be combined to make accurate predictions.

A more practical solution is to adopt image patches centered on each pixel, including its neighboring areas. This way we can train **convolutional neural networks** (or any suitable architecture) to predict the label of the center pixel. The image classification architectures we discussed earlier—such as CNNs, ResNet, or Vision Transformers (ViT)—can all be adapted to this task.

However, applying complete network computation to every pixel in the image would generate extremely high computational costs and cannot efficiently generate segmentation maps.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image29.png)

Another method is to train a **neural network** that takes the entire image as input and outputs a complete **segmentation map**—a matrix of labels rather than a single label. This method can effectively solve segmentation tasks.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image30.png)

To achieve this goal, we need an **input layer** that matches the image size and an expanded output layer. Traditional fully connected layers are not suitable because we want to generate images, which requires using fully convolutional neural networks (FCN).

Although FCN is effective, it also brings a challenge: overly large image sizes lead to massive network layers and a surge in the number of parameters that need optimization. This computational demand was particularly problematic when early **GPU performance** was limited, becoming a major bottleneck for algorithm training.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image31.png)

This algorithmic evolution process starts with full-size images and gradually reduces spatial resolution through downsampling operations. This process generates a low-resolution representation with increased channel count.

Subsequently, we upsample it back to the original image size to generate output pixels. Although **downsampling techniques** such as pooling operations and strided convolutions are quite mature, upsampling still presents challenges because we lack direct corresponding operations like inverse pooling or inverse strided convolution.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image32.png)

For this purpose, we introduce **new computational operations** that can essentially reverse the downsampling process. Before delving into upsampling, let me briefly explain the training principle of this network. Given a neural network that processes input images and outputs another image, the core tool in the training process is the **loss function**.

How to define or train this network through the loss function is the optimal solution? We have previously discussed **softmax loss functions**, regression loss functions, and SVM loss functions. If we choose the softmax loss function, the goal is to minimize the classification loss for each pixel, which is indeed the correct implementation path.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image33.png)

Since each pixel performs classification operations, we can calculate the **loss function** for each pixel. This involves summing the loss values for all pixels in the image, where the loss function adopts a simple softmax form, and then the backpropagation algorithm can be applied.

The **core problem** is whether the training process requires ground truth annotation data. In this case, ground truth segmentation labels must be provided because this type of algorithm belongs to fully supervised learning. Early training of such models required a large amount of manually annotated pixel-level labels, but modern tools no longer require this tedious operation.

Regarding **upsampling** operations, the processing flow is relatively intuitive.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image34.png)

We can adopt **unpooling operations**, which can be implemented in multiple ways. One method is **nearest neighbor interpolation**. For example, when upsampling from a 2x2 matrix to a 4x4 matrix, we simply copy each value from the low-resolution input.

Another method is Bed of Nails, which selects a single position in the enlarged output to retain the original value while setting the remaining positions to zero. Through continuous convolutional layer processing, these zero values will gradually be filled with effective data.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image35.png)

When using **max pooling** in the network encoding part, we can save the positions of selected maximum values and reuse these coordinates in the upsampling steps of the decoding part. This method is called **max unpooling**, and its core is to copy the saved maximum value positions to corresponding positions in the upsampled output.

Another solution is to adopt **learnable upsampling** methods. Unlike the parameter-free operations discussed earlier, learnable upsampling contains trainable parameters. To understand this, let's review convolution operations: in standard convolutional layers, we generate output by applying filters to each pixel. When performing downsampling, we use strided convolutions with stride 2 (rather than 1).

The same principle can be applied to upsampling. Each region in the upsampled image corresponds to a specific region, and we map it to output by defining weights. When overlaps occur between regions, overlapping values are typically summed.

For example: suppose there are one-dimensional input values A and B. We learn a filter to map these values to higher resolution output. This filter acts on each input value and writes the result to the output. When overlap occurs, output values from each position are summed.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image36.png)

We discussed **fully convolutional neural networks** and their applications. These are one of the most basic and widely used algorithms for segmentation tasks.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image37.png)

I want to briefly introduce a widely used network architecture—**U-Net**, named for its U-shaped design. This architecture remains highly practical today, especially in medical image segmentation. When not using foundation models, U-Net and its variants can still maintain **state-of-the-art performance** in segmentation tasks.

U-Net operates through two core stages: the **downsampling stage** reduces spatial information by expanding the receptive field, followed by the **upsampling stage** that restores the original image resolution. This architectural design concept completely aligns with the concepts I demonstrated earlier.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image38.png)

The **key difference** of this unit is that it's suitable for segmentation tasks, which requires preserving spatial information on the decoding end. Downsampling operations essentially reduce resolution, and if this information is not preserved during subsequent upsampling, reconstruction becomes difficult. This usually leads to blurred boundaries in the output.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image39.png)

To preserve **structural information** in the image and generate clearer output, the feature maps generated by the encoder are copied as input to each layer of the decoder. This concept forms the foundation of the **U-Net architecture**, which has been widely applied in practice.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image40.png)

Today, we discussed using fully convolutional neural networks for **semantic segmentation**. This architecture uses the same filters as before for downsampling. To save time, I skipped some slides, which can be referenced at the end of the presentation.

The **key operation** here is **transposed convolution**. We use a \\(3 \times 3\\) matrix, but instead of directly convolving the input data, we apply convolution to the transposed version of the input data. This operation generates larger output, essentially reversing the standard convolution process.

A common question is whether these filters are trained. The answer is yes—like standard convolutions, all filters are learned during the training process.

This concludes our discussion on semantic segmentation. For more details, please refer to the supplementary slides.

As mentioned earlier, we only obtain pixel-level labels. However, when multiple instances of the same **object** exist, since the output only provides pixel-level annotations, we cannot distinguish between them.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image42.png)

This leads to the topic of **instance segmentation**, where we not only perform pixel classification but also distinguish different instances, such as identifying different dogs in the image.

To achieve this, we must understand multiple objects in the image, which naturally transitions to the topic of **object detection**. Object detection, like image classification, remains one of the fundamental tasks in computer vision.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image43.png)

Over the years, numerous algorithms for **object detection** have been proposed. We will briefly outline some of these algorithms and highlight their key contributions. However, even limiting ourselves to the deep learning field, the related literature exceeds what this article can cover, especially research achievements from the past 10 to 15 years.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image44.png)

To solve the problem of single objects in **object detection**, we must perform classification to generate labels and class scores while obtaining bounding box coordinates. Specifically, we need to output box coordinates \\((x, y, h, w)\\) and the object's class. This defines the task of object detection.

The solution is straightforward. We can define a **softmax loss function** for class scores and a regression loss function for box coordinates—**L2 loss function**. By combining these two loss functions, we get a **multi-task loss function** that enables us to solve both tasks simultaneously. By adding the loss values, we create a composite loss function, as shown in the figure. This method is both simple and feasible.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image45.png)

If we only have one object, we can solve this problem using the architecture I discussed earlier. However, when **multiple objects** exist in the scene, the task becomes more challenging.

For three objects, we need to generate 12 output values, and complexity increases further as the number of objects increases. This method is not scalable because it simply extends the classification problem into a primitive form of **object detection**.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image46.png)

When handling multiple objects, one method is to use **bounding boxes** rather than the entire image as input. Each bounding box can be assigned a single label, such as *cat*, *dog*, or *background*. By classifying each bounding box separately, **sliding window techniques** can be applied. This technique needs to generate bounding boxes and slide them over the image, covering all possible combinations of coordinates \\((X, Y)\\) and dimensions \\((H, W)\\) to achieve object detection.

Through this process, the bounding box with the highest probability for each object can be identified. However, due to the large number of bounding box combinations, this algorithm has a core flaw of being **difficult to scale**.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image47.png)

In the early stages of the literature, especially before 2014, extensive research focused on identifying high-probability regions that might contain objects—these regions were called **candidate regions**. If these candidate regions can be effectively located, the problem becomes easier to handle because this aligns with the approach I described earlier.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image48.png)

For an image, if we have **candidate regions**, we can extract an image patch and process it with a **convolutional neural network** (CNN) to complete classification. Additionally, we can improve object detection by optimizing bounding box coordinates.

This method can both classify candidate regions and adjust bounding boxes as needed. This technique is called the **R-CNN algorithm**, one of the early object detection methods proposed at the CVPR 2014 conference.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image49.png)

These methods are very slow because they need to run complete **convolutional neural networks** for each bounding box. However, there are solutions: we can leverage the **spatial preservation properties** of convolution operations rather than processing each bounding box separately.

Since convolution operations preserve spatial information through downsampling or upsampling, we can track their positions in pixel space. Therefore, we suggest applying a single convolution operation to the entire image rather than processing individual image patches separately.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image50.png)

Now, we have obtained various regions in the feature map corresponding to the entire image. Next, we will detect these regions and apply a smaller **convolutional neural network (CNN)** to generate two outputs: **box offsets** for adjusting bounding boxes and object classes. This is the fast version of our CNN.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image51.png)

These are basic object detection algorithms based on **convolutional neural networks** with **bounding box localization** functionality. The number of candidate regions is predetermined.

I will briefly introduce the **Region Proposal Network**. This process involves placing bounding boxes on the image or its corresponding feature map while generating class labels and offsets to optimize the localization accuracy of detected objects.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image52.png)

This requires us to first use a Region Proposal Network (RPN) to generate bounding box region proposals to identify potential regions of interest in the image. The research focus is on developing RPN networks, which we achieve by randomly initializing CNN candidate box positions on the image.

Through convolutional layers, we optimize these regions based on their likelihood of containing objects and use object labels and position information for supervised optimization. The RPN adjusts bounding box coordinates with high object probability and finally outputs optimized bounding boxes.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image53.png)

I will leave the specific details about coordinates and dimensions for you to review later, as detailed discussion now would take too much time.

**The key point** is that for your question, we typically select the **top K regions with highest probability** as candidate proposals for this image, which are most likely to contain target objects.

This image is simple with only one object, so most regions are concentrated around it. But actual situations are usually not like this.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image54.png)

In different configurations, **region proposals** can be used to detect multiple targets with higher confidence scores.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image55.png)

After discussing **RCNN** and **Mask RCNN** in detail, it's important that you perform related calculations yourself, which will be very beneficial. However, due to high computational costs, these algorithms are no longer widely used today.

Understanding their historical significance is valuable, but the root of their inefficiency lies in requiring two independent networks: the **Region Proposal Network** and the **Classification and Bounding Box Optimization Network**. This means object detection for each image requires at least two forward passes.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image56.png)

Single-stage object detectors have made significant progress, such as the SSD series. The most famous representative is the **YOLO** algorithm. If you work in computer vision, you must be familiar with YOLO. Even today, YOLO maintains important status—although its early versions had high computational requirements due to using computationally intensive complex convolutional architectures.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image57.png)

In many industrial applications, YOLO (You Only Look Once) has become the foundational framework for object detection due to its speed and accuracy. This single-stage detector only needs to process the image once to simultaneously generate all bounding boxes and class probabilities. This method was proposed by Redmon et al. in 2015, achieving **real-time object detection** capabilities while maintaining high performance.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image58.png)

The working principle of this system is to divide the image into an **S×S grid**—in this case, a 7×7 grid. For each cell in the grid, the fully convolutional network outputs the probability of object existence and adjustment parameters for bounding boxes. Specifically, it generates **B bounding boxes** and related hyperparameters, representing adjustments for any objects detected within that cell. Additionally, it generates class probabilities for detected objects.

For example, when **B=2**, the network generates two bounding boxes with different probabilities. This process occurs simultaneously in all grid cells, with the same network generating corresponding outputs for each bounding box.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image59.png)

It generates multiple candidate boxes for objects, with each bounding box associated with a probability value. In this example, **probability** is reflected through the edge weights of each box. Based on this large amount of bounding box and object probability data, we can now apply threshold processing.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image60.png)

Additionally, this paper adopted an algorithm involving **non-maximum suppression** and threshold processing to identify the highest probability instances. Specific details are not repeated here.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image61.png)

This shows an intuitive implementation of **object detection**. Exploring the **YOLO codebase** is very beneficial, as many updated versions are widely used in medical, robotics, and industrial fields.

The key question is: How do we obtain the second image, and what's the principle behind it? As mentioned earlier, for each grid cell, we generate \\(B\\) bounding boxes—two in this example. Each box is associated with a **probability vector** representing the likelihood of object existence. By aggregating these boxes across all grid blocks, we get a large number of detection boxes with corresponding probabilities.

![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image62.png)

One of the newer methods in object detection is DETR (Detection Transformer), which is entirely based on transformer architecture. As discussed last week and revisited today, the same type of self-attention and cross-attention modules can generate object detection results and bounding boxes.

This method comes from a 2020 paper (ECCV 2020), and although now considered somewhat outdated for practical applications, it remains an excellent example of using transformers for object detection.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image63.png)

The process here is similar to what we discussed earlier. Images are first divided into multiple patches, which are then processed through convolutional neural networks (CNNs) to generate tokens. Positional encodings are added to these patches, defining the input tokens for the Transformer encoder. The encoder consists of multiple layers of self-attention mechanisms, layer normalization, and multi-layer perceptrons (MLPs), finally outputting processed tokens.

To generate bounding boxes, the algorithm intelligently uses the encoder's output tokens as input to the **Transformer decoder**. By introducing trainable query parameters—for example, inputting five, ten, or twenty queries—we can detect the corresponding number of target objects in the image. The decoder uses self-attention layers and cross-attention layers with encoder outputs to generate values for each query. These values are processed through **feedforward networks FFN** to output class labels and bounding box coordinates, or mark as no target detected.

The final output contains bounding boxes and their corresponding classes. It should be noted that not all possible bounding boxes are input into the Transformer for processing.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image64.png)

The input consists of trainable parameters that serve as query vectors, representing the target objects expected in the output. Unlike traditional methods, this system has no input box design but generates class labels and bounding box coordinates simultaneously as output. These query vectors structurally specify both the object features to be found and their spatial positions in the image.

Class labels adopt predefined forms and serve as part of the output, constituting the foundation of supervised learning. The algorithm identifies the types of classes to be detected through class probability vectors similar to other methods. Output results are supervised through training by calculating L2 loss between predicted boxes and ground truth boxes.

The query process doesn't explicitly guide the model on what objects to look for or where to look. Instead, the training process relies on backpropagation mechanisms to automatically correct output errors. The initial stage provides no specific instructions, with queries only requiring output of at most nine objects—this embodies the core concept of this method.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image65.png)

Through **self-attention** and **cross-attention** mechanisms, the model generates output tokens, which are then converted into classes and bounding box coordinates through **feedforward neural network** operations.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image66.png)

Your question is whether these queries correspond to image patches.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image67.png)

No, they are not image patches. These are **trainable parameters** used as queries to generate output results. For each input, the output contains class labels and bounding box coordinates. Object queries are initialized as learnable parameters, and the network optimizes these parameter values during training.

Regarding the question of assigning feedforward networks (FFN) to specific bounding boxes, there's no predefined mapping relationship. The network ensures each query can interact with the output layer through multiple layers of **self-attention** and **cross-attention** mechanisms, avoiding redundant outputs. Supervisory signals act on feedforward networks to guide their predictions.

This algorithm doesn't require pixel-level segmentation data for training, only class labels and bounding boxes are needed to run. But if pixel-level segmentation data exists, it can be converted to bounding boxes for training.

Regarding generalization to unseen object classes (new class labels), fully supervised networks typically cannot handle unknown classes without prior knowledge. Although background or "no object" labels are supported, **zero-shot learning** extension schemes for such algorithms might solve this limitation.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image68.png)

However, the problem is not always just about pixel values themselves. Understanding how various class activation mechanisms work is crucial, which leads to **Class Activation Mapping (CAM)**. Although CAM and **Grad-CAM** to be discussed later are the most mainstream interpretability algorithms for convolutional neural networks, they also apply to other architectures. However, for Transformer models, as mentioned earlier, we have more efficient interpretation methods.

In convolutional layers, pooling operations generate feature maps, which are then converted into scores. By expanding mathematical expressions, we can use weighted summation of weight values to highlight class scores. This enables us to trace class predictions back to feature maps and specific spatial positions in the image—because convolutional layers essentially map the spatial dimensions of the image.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image89.png)

Convolution operations **maintain spatial consistency** throughout all processing steps, enabling us to trace back to the original image space. By observing feature maps, we can see how **class activation** affects specific regions in the image. Multiplying learned weights with feature values generates these class activations.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image90.png)

This means we now have a method to return to image space. As long as we stay within convolutional space, we can trace back to the original image and generate **class activation maps**.

For example, for classes like palace, dome, church, altar, and monastery, different class activation maps can be created. These maps will highlight the **weights**, pixels, or regions in convolutional layers that affect scores for these specific classes.

The same principle applies to other cases, such as class activation maps for the same object in different images. But there's a limitation: this method can only be applied to the last convolutional layer because related calculations are limited to that layer.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image91.png)

To solve this problem, researchers developed a variant of this algorithm—**Grad-CAM (Gradient-weighted Class Activation Mapping)**. This method follows the same basic principles but improves the weight calculation process.

Unlike simply calculating the product of weights and features, we create weights based on these gradients through backpropagation. These **gradient-derived weights** replace the original weights, effectively aggregating all weights and gradients up to the target layer.

Finally, we apply the **ReLU activation function** to retain only positive values.



![](https://congo-blog.oss-cn-beijing.aliyuncs.com/blog-images/cs231n/lec9_image92.png)

This concept can also be fully demonstrated in image space within classes. The **Class Activation Mapping (CAM)** I discussed earlier only applies to the last convolutional layer, but this approach is often impractical because most CNN architectures don't end with a single convolutional layer—they typically include other operations like fully connected layers.

To pass class activation information through intermediate layers to convolutional layers, we often use **gradient weighting techniques**, essentially combining activation maps with aggregated gradients. This method enables effective visualization, generating heat maps for individual objects.
